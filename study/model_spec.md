# Exact pilot model

Study date: 20 October 2026. Main project type: simulation/modelling. One pending or approved course per synthetic student. The simulator is not a replica of the full SIS workflow.

## Parameters and data generation

Three courses A/B/C have 15 seats each. N=30/60/90 is varied. Each student's favourite is independently sampled with probabilities 0.60/0.25/0.15; its value is 1. Other course values are independent Uniform(0.3,0.8). All generated courses are acceptable, so placement and acceptable-course placement coincide. Initial requests are to favourites; a separately seeded permutation supplies their timestamps. No new students arrive after round 0.

Default cost per actual change c=0.05; subjective expected departure before the next approval rho=0.10. There are 12 rounds, with approvals after rounds 3/6/9/12. Status checking is scheduled at rounds 1, 1+k, 1+2k, ...; k=1 by default and k=3 in the slower-refresh scenario. Agents evaluate decisions every round using current public vacancies and status. N=60 higher-cost scenario uses c=0.15. Each of the five scenarios uses seeds 0–29 in both arms.

All random streams are keyed separately by seed and purpose: population, initial order and per-round full-population commit order. Behavioural changes cannot shift the random stream in another arm. `population_hash` covers all agents and initial order. There are no sampled external withdrawals. Rho changes forecasts only; actual queue departures are generated by decisions.

## Information and forecasting

Let C_j be course capacity; a_j is the publicly inferable number approved and v_j=C_j-a_j. The shared expected number pending is lambda_j=max(0, b*N*s_j-a_j), where s_j is the known synthetic favourite share and b=1 is the prior multiplier. This static approximation is not calibrated to endogenous switching. It is intentionally recorded for later sensitivity testing.

For rank r and v vacancies, the forecast is g(r,v)=P[Binomial(r-1,1-rho)<v]. This assumes independent departures among people ahead before the next approval. It equals zero for v=0 and one when r<=v. It does not account for further approvals or predict an equilibrium. Belief error can arise because departure choices are correlated and endogenous.

Visible students use g at their own last disclosed rank. Hidden students set m=max(1,ceil(lambda_current)) and average g over ranks 1...m, treating those ranks as equally likely. This is a bounded heuristic, not a proof of Bayesian optimality. Every new alternative request is evaluated using the same prior in both arms: P[Poisson(lambda_j*(1-rho))<v_j]. The Poisson distribution represents unobserved people already ahead of a new application; it is a belief distribution, not extra simulated agents.

Policies receive only an immutable Observation containing current course, public vacancies/approval counts, shared prior and possibly own cached rank/age. They never receive true alternative queues. Visible queries refresh only on scheduled ticks. Rank stays associated with the course where it was observed; switching invalidates it. Until the next scheduled query, a student who switched uses the same rank-prior calculation as a hidden student. When retained for the same course, a rank can become stale.

## Decisions and allocation

At each tick every pending, revising student compares p_current*u_current with p_j*u_j-c for all other currently open courses. Switch only if an alternative improves the best value by more than 1e-12. Exact/near ties stay; tied alternatives use the lower course ID. The same rule applies to both arms. An expected gain is not a guarantee of a realised gain.

All observations and decisions are computed from the tick-start state. Switches are then committed in a separately seeded random full-population order. Old requests are removed and new timestamps assigned. Vacancies depend only on approvals, so committing pending requests does not close a course before the approval step. Pending queues may exceed capacity. Approval takes the earliest timestamps up to remaining capacity; approved agents stop revising. Existing pending requests in full courses remain pending, but no new request can enter such a closed course. Final approval precedes waiting-list expiry.

## Outcomes

- Raw preference utility: value of the allocated course, or zero if unplaced; averaged over all original N students.
- Net utility: raw utility minus c times that student's actual switches; can be negative and is not money.
- Placement rate: placed/N; no-course count: N-placed.
- Switching: total actual course changes, and total/N. Each drop-and-rejoin receives a new timestamp.
- Demand: pending count and pending/C_j at a stated observation phase. Course inflow/outflow counts come from actual switch events.
- Pending HHI: sum of squared course shares among pending students, zero when none remain. Peak uses post-decision states only. HHI can rise simply because very few people remain; no herding conclusion may be drawn from HHI alone.
- Scheduled checks and rank disclosures are separate. Operation proxy = scheduled status checks + 2*switches. It is not server traffic or latency; supplied public metadata and initial submissions are not counted.

Summaries report means and sample SD across 30 seeds, plus within-seed visible-minus-hidden differences. These describe this synthetic experiment. No population-level p-values or empirical HKU effects are claimed.

## Worked example and boundaries

Two courses have one place each. S values A=10, B=5 and pays cost 1; the other student stays with A. Set rho=0 and one approval after one decision. Orders (S,other) and (other,S) are equally likely. Hidden S believes rank is 1 or 2 with equal probability, hence stay benefit 5 versus switch benefit 4. Visible S stays at rank 1 and switches at rank 2. Expected focal net utility is 7 visible versus 5 hidden. This controlled illustrative case is distinct from the N=30/60/90 pilot; it does not establish a general effect.

Main omissions: multiple-course bundles, strategic approved-course drops, enrolment cancellations, special priorities, new arrivals after round 0, heterogeneous checking schedules, empirically measured beliefs and actual SIS performance. Frozen approved allocations make the process stop offering new seats once all seats are filled. The 12-round status schedule is imposed rather than optimised by students. These restrictions are part of the interpretation, not hidden implementation details.

## Predefined next experiment

Keep N=60 and the same matched seeds while changing one factor at a time: prior multiplier b=0.5/1.5; belief rho=0/0.3; alternative values Uniform(0.1,0.4) or Uniform(0.6,0.9); switching cost c=0; and sequential rather than synchronous action. For sequential action, reuse the keyed per-round order but refresh/observe, decide and commit one agent at a time before approval. These follow-up scenarios are designed but not part of the 300 completed pilot runs. Approved-course withdrawals and later arrivals need a separate extension with explicit event schedules.
